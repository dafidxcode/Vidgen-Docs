Vidgen models are managed from the server and can change at any time — new models are added, old ones are retired, and credit prices are adjusted. So **do not hardcode the model list** in your product. Read it at runtime:

```bash theme={null}
curl https://vidgen.id/api/v1/models
```

This endpoint is public (no API key) and returns three buckets: `video`, `image`, `audio`. Only active models are returned.

## Shape of one entry

```json theme={null}
{
  "id": "seedance-2-5-flash",
  "label": "Seedance 2.5 Flash",
  "category": "Video",
  "mode": "video",
  "creditsDefault": 3,
  "priceMatrix": { "20": 3 },
  "capabilities": {
    "durations": ["20"],
    "ratios": ["16:9", "9:16"],
    "resolutions": ["720p"],
    "maxReferenceImages": 0,
    "maxReferenceVideos": 0,
    "maxReferenceAudios": 0
  }
}
```

| Field | Meaning |
| --- | --- |
| `id` | The value you send in the `model` field of the body. |
| `label` | Display name. It can change; do not use it as a logic key. |
| `category` | `Video` \| `Image` \| `Audio`. |
| `mode` | Same as `category` but lowercase; used to pick the parameter tab. |
| `creditsDefault` | Base price in credits when no override matches. |
| `priceMatrix` | Per-key overrides: `"15"`, `"720p"`, `"720p:15"`, or `"low:2K"` (quality:resolution). |
| `capabilities.durations` | Valid values for `parameters.duration`. |
| `capabilities.ratios` | Valid values for `parameters.ratio`. `auto` is always accepted and is not validated. |
| `capabilities.resolutions` | Valid values for `parameters.resolution`. |
| `capabilities.maxReferenceImages` / `Videos` / `Audios` | How many references of that kind you may send. |
| `capabilities.minReferenceVideos` | MINIMUM number of reference videos. When present, a request without a video is answered `400` before any credit is deducted. |

Some models also return `qualities`, `backgrounds`, `outputFormats`, `supportsNegativePrompt`, or `supportsSeed`. If the key is absent, the server ignores that parameter — no error, no effect.

## Parameters the API understands

Only the following keys are read from the `parameters` object:

| Key | Applies to | Notes |
| --- | --- | --- |
| `duration` | Video | You may write `"5"` or `"5s"`; the trailing `s` is stripped. |
| `resolution` | Video, Image | Validated against `capabilities.resolutions`. |
| `ratio` | Video, Image | The alias `aspect_ratio` is also accepted. |
| `quality` | Image | Only if the model has `qualities`. |
| `background` | Image | Only if the model has `backgrounds`. |
| `output_format` (or `format`) | Image, Audio | Only if the model has `outputFormats`. |
| `negative_prompt` | Some models | Only if `supportsNegativePrompt`. |
| `seed` | Some models | Only if `supportsSeed`. |
| `orientation` | Motion control only | `image` or `video`. |

Other keys you send (for example `style`, `title`, `camera`) are **not** processed and are not stored as an error. Validation happens before the job is created, so a typo in `parameters` fails silently.

<Note>
  If you need a parameter that does not exist yet, send a request through support. Adding a new key will not break existing integrations.
</Note>

## Hard limits per model

Some models accept only certain values. `capabilities` in the catalog is the source of truth, but the table below lists the limits that get sent wrong most often. A value outside the list is not validated by our API before the job is created — the request is forwarded to the generator, the job ends as failed, and the credits are refunded in full.

| Model (`id`) | Category | Durations | Resolutions | References |
| --- | --- | --- | --- | --- |
| `muse-video` | Video | `10` `20` `30` `40` `50` `60` seconds | `720p` only | 4 images |
| `minimax-h3` | Video | `5` `10` `15` seconds | `2K` only | 9 images, 3 videos, 3 audios |
| `gemini-omni-flash-1-1` | Video | `10` seconds only | `720p`, `1080p` | 7 images |
| `kling-4.0` | Video | `5` `10` `15` `30` seconds | `720p`, `1080p` | 10 images |
| `gpt-image-2.6-sunburst`, `gpt-image-2.6-flare` | Image | — | `1K`, `2K`, `4K` | 16 images |
| `gpt-image-2.5-sunburst`, `gpt-image-2.5-flare` | Image | — | `1K`, `2K`, `4K` | see catalog |
| `nano-banana-2-lite` | Image | — | `1K` only | 14 images |
| `nano-banana-2`, `nano-banana-2.1` | Image | — | `512px`…`4K` | 14 images |
| `nano-banana-pro` | Image | — | `1K`, `2K`, `4K` | 14 images |
| `seedream-5.0-lite` | Image | — | `2K`, `3K` | 10 images |
| `seedream-5.0-flash`, `seedream-5.0-pro` | Image | — | `1K`, `1.5K`, `2K` | 10 images |
| `wan2.7-image-spicy` | Image | — | `1K`, `2K` | 9 images |
| `wan2.7-image-pro-spicy` | Image | — | `1K`, `2K`, `4K` | 9 images |

Two things worth reading before those numbers:

- **Quality changes the price on image models.** On `gpt-image-2.6-*`, `quality` affects the charge through keys such as `"low:1K"` … `"max:4K"` in `priceMatrix`. The same resolution can differ by more than an order of magnitude, so do not assume `creditsDefault` is your worst case.
- **Ratios are a list, not a free field.** `muse-video` and `minimax-h3` each have their own ratio set; `gemini-omni-flash-1-1` accepts only `16:9` and `9:16`. `auto` is always accepted and never validated.

## Id matching

`model` is matched against the id column in the catalog, and spellings with dots and hyphens are treated as equivalent:

```text theme={null}
seedance-2-5-flash  ==  seedance.2.5.flash
```

Some ids have internal aliases (for example `vidgen-1.0`). The recommendation stays the same: use the `id` exactly as it appears in the `GET /api/v1/models` response.

Models that are currently disabled **stay in** the database so that old history keeps its labels, but they do not appear in the catalog and cannot be run. A request for an inactive model is answered `409`.

## Motion control models

Models with motion transfer capability have their own rules, and there are two different duration behaviours:

- `prompt` may be empty — the motion comes from the reference video.
- **Kling Motion Control** (`kling-mc-3-0`, `kling-mc-3-0-pro`): the length of the reference video determines the output duration (and the price), not the number you send in `parameters.duration`.
- **Vidgen Motion** (`vg-motion`): the duration comes from `parameters.duration` (the catalogue currently offers 15 seconds only), and the price follows `resolution` (`720p` / `480p`). A reference video longer than the chosen duration is trimmed on the server.
- Reference duration limits are looser than for regular models; see [Reference media](/en/concepts/reference-media).

<Note>
  `capabilities.motion` is not exposed by `GET /api/v1/models` — it returns only `durations`, `ratios`, `resolutions`, and the reference-count limits. So over the API the "duration comes from the video" behaviour has to be known from the model id, not read from the catalogue. If you need to filter programmatically, ask through support before hardcoding a list of ids.
</Note>

## Audio

The catalog includes an `audio` bucket, but audio generation through an API key **is not open yet**. Sending `mode: "audio"` today creates a job that fails partway through with a credit refund. Audio generation is still dashboard-only.

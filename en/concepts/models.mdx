Vidgen models are managed from the server and can change at any time — new models are added, old ones are retired, and credit prices are adjusted. So **do not hardcode the model list** in your product. Read it at runtime:

```bash theme={null}
curl https://vidgen.id/api/v1/models
```

This endpoint is public (no API key) and returns three buckets: `video`, `image`, `audio`. Only active models are returned.

This page is a complete per-model reference as of **8 November 2026**. The numbers are useful for building UI and estimating cost, but `GET /api/v1/models` remains the single source of truth while your code runs.

## Shape of one entry

```json theme={null}
{
  "id": "gpt-image-2.6-sunburst",
  "label": "GPT Image 2.6 Sunburst",
  "category": "Image",
  "mode": "image",
  "creditsDefault": 1,
  "unlimitedOnly": false,
  "priceMatrix": {
    "1K": 2, "2K": 3, "4K": 5,
    "low:1K": 1, "low:2K": 2, "low:4K": 3,
    "medium:1K": 2, "medium:2K": 3, "medium:4K": 5,
    "high:1K": 2, "high:2K": 4, "high:4K": 6,
    "xhigh:1K": 3, "xhigh:2K": 6, "xhigh:4K": 10,
    "max:1K": 7, "max:2K": 13, "max:4K": 21
  },
  "capabilities": {
    "durations": [],
    "ratios": ["1:1", "2:3", "3:2", "3:4", "4:3", "4:5", "5:4", "9:16", "16:9", "21:9"],
    "resolutions": ["1K", "2K", "4K"],
    "qualities": ["low", "medium", "high", "xhigh", "max"],
    "backgrounds": ["auto", "opaque", "transparent"],
    "outputFormats": ["png", "jpeg", "webp"],
    "maxReferenceImages": 16,
    "maxReferenceVideos": 0,
    "maxReferenceAudios": 0
  }
}
```

| Field | Meaning |
| --- | --- |
| `id` | The value you send in the `model` field of the body. |
| `label` | Display name. It can change; do not use it as a logic key. |
| `category` | `Video` \| `Image` \| `Audio`. |
| `mode` | Same as `category` but lowercase; used to pick the parameter tab. |
| `creditsDefault` | Base price in credits when no override matches. |
| `unlimitedOnly` | `true` when the model is only available to accounts with an active Unlimited plan. Without a subscription the request is answered `403`. |
| `priceMatrix` | Per-key overrides: `"15"`, `"720p"`, `"720p:15"`, or `"low:2K"` (quality:resolution). |
| `capabilities.durations` | Valid values for `parameters.duration`. |
| `capabilities.ratios` | Valid values for `parameters.ratio`. `auto` is always accepted and is not validated. |
| `capabilities.resolutions` | Valid values for `parameters.resolution`. |
| `capabilities.qualities` | Valid values for `parameters.quality`. Only on some image models. |
| `capabilities.backgrounds` | Valid values for `parameters.background`. |
| `capabilities.outputFormats` | Valid values for `parameters.output_format`. |
| `capabilities.supportsNegativePrompt` | When `true`, `parameters.negative_prompt` is forwarded. |
| `capabilities.supportsSeed` | When `true`, `parameters.seed` is forwarded. |
| `capabilities.maxReferenceImages` / `Videos` / `Audios` | How many references of that kind you may send. |
| `capabilities.minReferenceVideos` | MINIMUM number of reference videos. When present, a request without a video is answered `400` before any credit is deducted. |
| `capabilities.feature` | `"create"` or `"motion"`. Motion models have their own duration rules. |
| `capabilities.motion` | Reference duration range (`minDurationSec`, `maxDurationSec`) and whether the output duration comes from the reference video. |
| `capabilities.modes` / `versions` | Audio only: songwriting mode and engine version. |

A missing key means the server ignores that parameter — no error, no effect.

## Parameters the API understands

Only the following keys are read from the `parameters` object:

| Key | Applies to | Notes |
| --- | --- | --- |
| `duration` | Video | You may write `"5"` or `"5s"`; the trailing `s` is stripped. |
| `resolution` | Video, Image | Validated against `capabilities.resolutions`. |
| `ratio` | Video, Image | The alias `aspect_ratio` is also accepted. |
| `quality` | Image | Only if the model has `qualities`. Also affects the price. |
| `background` | Image | Only if the model has `backgrounds`. |
| `output_format` (or `format`) | Image, Audio | Only if the model has `outputFormats`. |
| `negative_prompt` | Some models | Only if `supportsNegativePrompt`. |
| `seed` | Some models | Only if `supportsSeed`. |
| `orientation` | Motion control only | `image` or `video`. |

Other keys you send (for example `style`, `title`, `camera`) are **not** processed and are not stored as an error. Validation happens before the job is created, so a typo in `parameters` fails silently and the default is used.

<Note>
  If you omit `duration` or `resolution`, the server uses the first entry of the model's capability list, and the price is computed from that value. Send them explicitly when you need a specific combination.
</Note>

### Input modes served by video models

Vidgen derives the mode from the references you send — you do not write `mode` in the body. The order is:

| References sent | Mode that runs |
| --- | --- |
| None | Text-to-video |
| Images only | Image-to-video (one image = animate it; several images = a sequence) |
| Video + image | Reference-to-video: the video is the motion source, the image is the character identity |
| Video only | Rejected on the Gemini Omni family; other models treat it as a reference video |

Two models have tighter limits than the general table:

- **`gemini-omni-1.1-unlimited`** accepts text or **exactly one** image (SFV). Reference video is rejected (`maxReferenceVideos: 0`).
- **`gemini-omni-1.2-unlimited`** accepts one to three images (I2I), or one video **together with** one image (R2V). A video without a paired image is rejected.

## Unlimited models

Three models run without credit charge: two labelled `(Unlimited)` and `seedance-2-5-flash`. All three are `unlimitedOnly: true` with `creditsDefault: 0`.

```json theme={null}
{
  "id": "gemini-omni-1.2-unlimited",
  "label": "Gemini Omni 1.2 Flash (Unlimited)",
  "creditsDefault": 0,
  "unlimitedOnly": true,
  "priceMatrix": {},
  "capabilities": {
    "durations": ["15"],
    "resolutions": ["720p", "1080p"],
    "ratios": ["16:9", "9:16", "1:1"],
    "maxReferenceImages": 3,
    "maxReferenceVideos": 1,
    "maxReferenceAudios": 0,
    "feature": "create"
  }
}
```

The rules:

- An account **without** an active Unlimited plan that calls this id is answered `403`, not `402`. No credits are deducted.
- An account **with** an active plan pays 0 credits, from the dashboard or from an API key.
- Both remain subject to the 2 concurrent jobs and 50 successful videos per day limits. See [Concurrency & usage limits](/en/concepts/concurrency-limits).
- `gemini-omni-1.2-unlimited` uses a 1-20 queue in Vidgen: a user may queue up to 20 jobs, but the server forwards them one at a time to the generator. `gemini-omni-1.1-unlimited` and `seedance-2-5-flash` use the parallel booster queue.

```json 403 theme={null}
{
  "error": "Model \"Gemini Omni 1.2 Flash (Unlimited)\" hanya tersedia untuk paket Unlimited aktif.",
  "code": "unlimited_required",
  "model": "gemini-omni-1.2-unlimited"
}
```

<Warning>
  Do not filter Unlimited models from `creditsDefault === 0`. Use `unlimitedOnly`. Other promotional models can be zero-priced temporarily without requiring a subscription.
</Warning>

### Complete image request example

```bash theme={null}
curl -X POST https://vidgen.id/api/v1/generate \
  -H "Authorization: Bearer vg_KEY_KAMU" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-image-2.6-sunburst",
    "prompt": "leather sneaker product photo on a marble table, window light from the left",
    "parameters": {
      "resolution": "2K",
      "ratio": "4:5",
      "quality": "high",
      "background": "opaque",
      "output_format": "webp"
    },
    "references": [
      { "url": "https://cdn.yourshop.com/shoe-1.png", "type": "image" },
      { "url": "https://cdn.yourshop.com/shoe-2.png", "type": "image" }
    ],
    "idempotencyKey": "sku-8841-front-webp"
  }'
```

That request is billed at `high:2K` = **4 credits**, not the `creditsDefault` of 1. References add no cost today.

## Price lookup order

The server follows this order exactly. Mirror it on your side if you want to show an estimate before sending:

```text theme={null}
quality:resolution  →  resolution:duration  →  duration  →  resolution  →  creditsDefault
```

Duration keys are tried in several spellings (`"15"`, `"15s"`) and combined keys in both orders (`"720p:15"` and `"15:720p"`), so you do not need to normalise them yourself. The reference surcharge is currently **0** for every kind and count of reference.

## Id matching

`model` is matched against the id column in the catalog, and spellings with dots and hyphens are treated as equivalent:

```text theme={null}
seedance-2-5-flash  ==  seedance.2.5.flash
```

Some ids have internal aliases. The recommendation stays the same: use the `id` exactly as it appears in the `GET /api/v1/models` response.

Models that are currently disabled **stay in** the database so that old history keeps its labels, but they do not appear in the catalog and cannot be run. A request for an inactive model is answered `409`.

<Note>
  Two models can have similar display names but different ids, prices, and capabilities — for example `gemini-omni-flash-1-1` (paid, 7 image references) and `gemini-omni-1.1-unlimited` (Unlimited quota, 3 images, no video). Always choose by `id`, never by `label`.
</Note>

## Motion control models

Models with `capabilities.feature: "motion"` have their own rules:

- `prompt` may be empty — the motion comes from the reference video.
- `parameters.duration` is **ignored**. The server measures the reference video, rounds up, and uses that as the output duration.
- `parameters.orientation` chooses whether the output ratio follows the character image (`image`) or the motion video (`video`).
- Reference duration limits are looser than for regular models: 3–30 seconds, and the video is not auto-trimmed. See [Reference media](/en/concepts/reference-media).

Two models are active in this group: `kling-mc-3-0` (duration from the video) and `vg-motion` (duration selected, 15 seconds). `capabilities.feature` and `capabilities.motion` are published in the catalog, so you can filter programmatically:

```js theme={null}
const motionModels = models.video.filter((m) => m.capabilities.feature === "motion");

for (const m of motionModels) {
  const range = m.capabilities.motion; // { minDurationSec: 3, maxDurationSec: 30 }
  console.log(m.id, range?.minDurationSec, range?.maxDurationSec);
}
```

Some motion models add `durationFromReference` to that object. When the key is absent, treat the duration as coming from the reference video — that is the default behaviour of the motion group.

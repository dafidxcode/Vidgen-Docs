Motion control mengambil **gerakan** dari sebuah video dan menerapkannya ke **karakter** pada gambar kamu. Hasilnya video baru: wajah dan gaya dari gambar, gerakan dari video.

Model kelompok ini ditandai `capabilities.feature === "motion"` di [`GET /api/v1/models`](/api-reference/models). Dua yang aktif: `kling-mc-3-0` (durasi dari video) dan `vg-motion` (durasi 15 detik, sampai 10 gambar + 5 video referensi). Contoh di bawah memakai `kling-mc-3-0`:

| Field | Nilai |
| --- | --- |
| `id` | `kling-mc-3-0` |
| `label` | Kling Motion Control 3.0 Standard |
| `creditsDefault` | 3 (datar) |
| `priceMatrix` | `{}` — tidak ada override |
| `capabilities.resolutions` | `720p` |
| `capabilities.ratios` | `16:9`, `9:16` (ditentukan `orientation`, bukan `ratio`) |
| `capabilities.maxReferenceImages` | 1 |
| `capabilities.maxReferenceVideos` | 1 |
| `capabilities.motion` | `{ "minDurationSec": 3, "maxDurationSec": 30 }` |

<Tip>
  Jangan hardcode `kling-mc-3-0`. Saring katalog dengan `capabilities.feature === "motion"` supaya kodemu tetap jalan saat model motion bertambah atau berganti.
</Tip>

```js theme={null}
const { models } = await (await fetch("https://vidgen.id/api/v1/models")).json();
const motion = models.video.filter((m) => m.capabilities.feature === "motion");

for (const m of motion) {
  console.log(m.id, m.creditsDefault, m.capabilities.motion);
}
```

## Alur tiga langkah

<Steps>
  <Step title="Unggah video gerakan">
    Sertakan id model target supaya server memakai aturan durasi motion (3–30 detik) dan **tidak** memotong videonya jadi 14,5 detik.

```bash theme={null}
curl -X POST https://vidgen.id/api/v1/upload \
  -H "Authorization: Bearer vg_KEY_KAMU" \
  -F "file=@gerakan.mp4" \
  -F "model=kling-mc-3-0"
```

    Responsnya berisi `asset.duration`. Simpan angka itu — durasi keluaranmu akan sama dengannya (dibulatkan ke atas).
  </Step>
  <Step title="Unggah gambar karakter">
    Foto atau ilustrasi yang ingin dianimasikan. Wajah menghadap depan memberi hasil paling stabil. Unggah dengan `model` yang sama.

```bash theme={null}
curl -X POST https://vidgen.id/api/v1/upload \
  -H "Authorization: Bearer vg_KEY_KAMU" \
  -F "file=@karakter.png" \
  -F "model=kling-mc-3-0"
```
  </Step>
  <Step title="Kirim job dengan kedua referensi">
    Urutan tidak menentukan peran — yang membedakan adalah field `type`. Tepat satu gambar dan satu video; lebih atau kurang dijawab `400`.

```json theme={null}
{
  "model": "kling-mc-3-0",
  "prompt": "",
  "references": [
    { "id": "ref_api_1762261900_gerakan.mp4", "type": "video", "url": "/api/media/ref_api_1762261900_gerakan.mp4" },
    { "id": "ref_api_1762261901_karakter.png", "type": "image", "url": "/api/media/ref_api_1762261901_karakter.png" }
  ],
  "parameters": { "orientation": "video" }
}
```

    `prompt` boleh string kosong: server mengisinya dengan instruksi netral sebelum diteruskan.
  </Step>
</Steps>

## Aturan yang ditegakkan server

| Aspek | Aturan |
| --- | --- |
| `prompt` | Boleh kosong. Maksimal 2.500 karakter; lebih dari itu ditolak `400` sebelum kredit terpotong. |
| `parameters.duration` | Diabaikan. Server mengukur ulang video referensi tersimpan dan menimpa nilainya. |
| Pembulatan durasi | Ke atas (`Math.ceil`). Video 10,2 detik dihitung 11 detik. |
| Rentang video referensi | 3–30 detik, dibaca dari `capabilities.motion`. Di luar rentang → `400`. |
| Jumlah referensi | Tepat 1 gambar + 1 video. |
| `parameters.orientation` | `"image"` atau `"video"`. Nilai lain jatuh ke `"video"`. |
| `orientation: "image"` | Video referensi maksimal 10 detik. Lebih panjang → `400` dengan pesan menyuruh pindah ke `"video"`. |
| `parameters.ratio` | Tidak menentukan rasio keluaran di model motion; `orientation` yang menentukan. |
| Harga | 3 kredit datar untuk model yang aktif sekarang. `priceMatrix` kosong, jadi panjang video tidak mengubah tagihan. |

<Warning>
  Harga motion control **tidak selalu** datar. Model motion lain bisa mengisi `priceMatrix` per detik. Selalu hitung perkiraan biaya dari `priceMatrix` + `creditsDefault` model yang kamu pilih, jangan dari angka di halaman ini.
</Warning>

## Kenapa durasi tidak bisa kamu tentukan sendiri

Server mengukur ulang panjang video dari berkas yang benar-benar tersimpan, lalu menimpa `parameters.duration` dengan hasilnya. Kalau server percaya angka dari klien, video 30 detik bisa dilaporkan sebagai 3 detik dan lolos dari batas `maxDurationSec`.

Artinya: kalau butuh keluaran 6 detik, **potong video referensinya jadi 6 detik sebelum diunggah**. Mengirim `duration: "6"` bersama video 20 detik tidak memperpendek apa pun.

## Format video referensi

Ekspor **MP4** kalau bisa. WebM tidak langsung ditolak: untuk model motion server mengonversinya ke MP4 lebih dulu supaya durasinya terbaca. Konversi memakai ffmpeg di server, jadi berkas rusak atau stream tanpa metadata panjang tetap dijawab:

```json 400 theme={null}
{
  "error": "Durasi video referensi tidak bisa dibaca. Unggah ulang videonya (format MP4) sebelum generate."
}
```

Transcode sendiri lalu unggah ulang:

```bash theme={null}
ffmpeg -i gagal.webm -c:v libx264 -preset veryfast -crf 20 -movflags +faststart keluar.mp4
```

Selain durasi, video referensi juga harus memenuhi batas umum: total piksel ≥ 300.000 dan sisi terpendek ≥ 360 px. Detail lengkap ada di [Media referensi](/concepts/reference-media).

## Contoh lengkap: unggah sampai hasil

```js motion_control.js theme={null}
import { readFile } from "node:fs/promises";

const BASE = "https://vidgen.id/api/v1";
const headers = { Authorization: `Bearer ${process.env.VIDGEN_API_KEY}` };

async function upload(path, filename, mime, model) {
  const form = new FormData();
  form.append("file", new Blob([await readFile(path)], { type: mime }), filename);
  form.append("model", model);
  const res = await fetch(`${BASE}/upload`, { method: "POST", headers, body: form });
  if (!res.ok) throw new Error(`upload ${filename}: ${res.status} ${await res.text()}`);
  return (await res.json()).asset;
}

const MODEL = "kling-mc-3-0";
const gerakan = await upload("gerakan.mp4", "gerakan.mp4", "video/mp4", MODEL);
const karakter = await upload("karakter.png", "karakter.png", "image/png", MODEL);

const res = await fetch(`${BASE}/generate`, {
  method: "POST",
  headers: { ...headers, "Content-Type": "application/json" },
  body: JSON.stringify({
    model: MODEL,
    prompt: "",
    references: [gerakan, karakter],
    parameters: { orientation: "video" },
    idempotencyKey: `mc-${karakter.id}-${gerakan.id}`,
  }),
});

const { job } = await res.json();
console.log(job.id, job.status, job.creditsCharged);
// Lanjutkan dengan polling GET /jobs/{id} — lihat panduan Node.js.
```

<Note>
  `idempotencyKey` di contoh itu dibentuk dari id kedua aset, jadi pasangan referensi yang sama tidak akan tertagih dua kali bila request diulang. Ganti pola itu bila kamu memang ingin hasil berbeda dari berkas yang sama.
</Note>

## Check-list sebelum kirim

<AccordionGroup>
  <Accordion title="Video gerakan">
    Satu berkas MP4, 3–30 detik (maksimal 10 detik bila `orientation: "image"`). Gerakan terlihat jelas, subjek tidak keluar frame, pencahayaan stabil, tidak ada teks yang dibakar ke gambar.
  </Accordion>
  <Accordion title="Gambar karakter">
    Tepat satu gambar. Sisi terpendek minimal 300 px, wajah menghadap depan, tidak tertutup objek, gaya konsisten dengan yang kamu inginkan di hasil akhir.
  </Accordion>
  <Accordion title="Model masih aktif?">
    Ambil `GET /api/v1/models` dan pastikan id motion-mu ada di sana. Model yang dinonaktifkan dijawab `409`, bukan `400` — jangan coba ejaan lain, pindah ke model yang tersedia.
  </Accordion>
  <Accordion title="Biaya dan saldo">
    Cek `GET /api/v1/user/credits` sebelum mengirim batch. motion control tetap memakan kuota video harian dan tunduk pada batas proses bersamaan seperti generate biasa.
  </Accordion>
</AccordionGroup>
